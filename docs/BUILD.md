# 实施与验收

## 开工前的小检查

检查目录、Python/Node 环境、已安装 CLI；核实上游协议并记录实际版本。默认采用 Python 3.11+、FastAPI、React + TypeScript + Vite；锁定施工环境中实际验证可用的依赖，而不是逐个追逐最新版。后端 SQLite 单进程，不引入 Redis、Celery、LangGraph、向量服务或新的代理框架。

检查属于施工的一部分，不单独扩成一个大型 Phase 0 项目。新建 `docs/INTEGRATION_STATUS.md` 保存实际外部探针，保留无法联网/认证的事实。

## 阶段 1：可操作的研究垂直切片

**用户路径：配置 → 导入一道题 → 启动 Run → 看见两类代理事件 → 指导/暂停 → 保存经验 → 重启仍能看到。**

实现最小前后端、数据库与文件存储、三个页面、配置/秘密分离、事件 SSE、经验编辑/历史、控制器和 Prime 薄适配器。大脑优先接当前机器可用的一种（Codex 或 Kimi），另一个显示尚未接入，不能假实现为同一普通 LLM。

同时提供明确的 Demo 模式，覆盖没有任何账户时的完整交互；Demo 只供 UI/状态机测试。真实模式至少完成已安装 CLI 的握手/状态探针；有显式模型测试授权后才做真实大脑 Decision + Prime 工具往返。

验收交付必须有可执行命令，例如最终实现的 `uv sync`、前端依赖安装/构建，以及 `uv run cyberscientist serve`。这些是目标命令，由实现后实测确认；本包自身不提供可运行后端。启动过程报出缺项，不在后台偷偷安装/更新全局 CLI。

该阶段结束时应有能操作的真实应用，即使某外部连接仍待授权。只有 Demo 跑通可称“离线垂直切片完成”，不能称“真实代理联调完成”。

## 阶段 2：真实远程科研与提交闭环

接通 bohr 的 Job 提交/查询/取消/取回，以及项目级 Prime Python skill。实现题目/规则快照、实验 manifest、checkpoint、操作日志、Bohrium-first 来源校验、两步 Attempt/bundle 提交和评分/资格核对。

在用户授权的单题和小预算范围内完成一次远程 smoke 与正式或练习提交；演练一次后端重启，确保挂接已有 Job、不产生重复 Attempt。没有权限时完成适配器代码、协议 fixture 测试、待实测清单，不将缺凭据误归为实现已完成。

**此阶段的真实验收终点：从 UI 启动一次研究，得到关联代码/输入/Job/产物的结果包，并能核对真实官方反馈。** 不要求首个题目高分，不为追求演示成绩绕过规则。

## 阶段 3：可替换大脑与获胜策略验证

接通第二种大脑，复用同一契约、事件与经验层；完成原生认证和恢复差异测试。补齐候选经验的全局晋升、失败历史检索、当前经验/运行快照对照。

执行两个有界、一次只改变一个变量的对照：先“Prime 单独执行 vs Prime + 大脑”，固定执行模型、工具、题目、总预算与可用证据；再固定较好的架构比较“无经验继承 vs 有经验继承”。监督消耗计入总预算，不能给监督组额外资源后宣称架构胜出。

第一对照禁止跨运行学习污染：经验快照固定、工作目录隔离、不向一组泄漏另一组产物。经验对照使用明确训练/测试划分；区分同题继续优化与跨题迁移。至少记录多个独立重复或明确样本不足，不以一次最佳成绩证明普遍优势。

如监督无增益，保留前端、执行/提交可靠性和经验编辑，让监督可关闭；不因为架构已经写好就强制所有实验使用它。

## 必须验证的关键情形

以下按流程测试，不需要拆成十几张独立施工卡。

| 情形 | 验收结果 |
|---|---|
| 未配置凭据 | UI 可用；说明缺项；不发起真实付费操作 |
| Profile 保存/切换 | 大脑、Prime、Playground、Bohrium 凭据不串用；新配置不覆盖旧 Trial 快照 |
| 真实模型工具往返 | 记录工具请求、执行、结果回传和终态；普通文本回复不算通过 |
| 原生运行时审批请求 | 能显示/按有限策略处理；不悬挂或自动全同意 |
| 指导与暂停 | queued 不假装已生效；暂停不假装远程 Job 已停 |
| 页面断连/刷新 | Run 不重启；SSE 补发，关键事件无重复 |
| 后端崩溃后恢复 | 已知 Job 重新挂接；Python 内存不被假定恢复 |
| 创建 Attempt 响应丢失 | 标记 unknown，先对账；不自动重发创建 |
| 重复点击提交 | 同 operation_id/同冻结提交意图不会创建重复外部动作 |
| 评分等待/错误/赛后练习 | 与科学失败及有效比赛分数分开 |
| 外部编辑经验后 UI 保存 | 409 冲突；不丢双方内容；旧 Run 仍使用旧快照 |
| 预算/密钥/结果包 | 超额停止新增受控操作；日志、导出、zip 不含秘密；未知费用不显示零 |

单元测试验证状态转换与校验；协议测试验证真实/显式 synthetic fixture；集成测试使用可控假服务注入超时；浏览器测试验证 UI；真实 smoke 记录授权与外部 ID。真实外部测试默认不进无凭据 CI。

## 工程完成标准

可从干净工作区按 README 安装/启动；能够定位出错的连接、Run 与外部操作；版本锁与测试证据可追溯；核心流程没有藏在 console 的按钮；所有“成功”有对应证据。形成一次有界代码审查，修复阻断项即可，不做无限 validator/reviewer 循环。

交付报告更新 STATUS：实现了什么、实际跑了什么、未跑什么、缺少哪项配置/权限。最多三个阶段；不要继续拆成几十个未来系统。
