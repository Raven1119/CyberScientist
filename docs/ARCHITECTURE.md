# 架构与运行语义

## 总体结构

```text
浏览器：研究工作台 / 经验库 / 连接设置
                 │ 同源 HTTP + SSE
                 ▼
Python 单进程后端
  RunController ─── SQLite（状态、事件、操作日志、经验修订）
       │            文件工作区（题目、代码、证据、运行快照）
       ├── BrainRuntime：Codex App Server 或 Kimi Wire
       ├── PrimeRuntime：独立 Prime Agent RPC 子进程
       ├── PlaygroundClient：题目、Attempt、评分反馈
       └── BohriumCompute：由受控后端调用 bohr
                             │
                             ▼
                      Bohrium 科学计算 Job
```

架构图是系统设计，不表示上述组件已经实现。前端和后端共用同一应用域；后端生产模式提供前端构建产物。Vite 开发模式代理 `/api`，不创建跨域凭据旁路。

## 大脑、执行器、控制器

| 组件 | 拥有的责任 | 不拥有的责任 |
|---|---|---|
| 大脑 | 研究意图、证据审阅、诊断、下一步方向、经验候选与晋升建议、提交建议 | 无限轮询、直接掌握平台密钥、悄悄改预算/授权 |
| Prime | 一轮实验的具体方法、脚本、文献使用、远程任务请求、结果报告 | 无权限直接提交比赛或改全局经验；不改控制器 |
| 控制器 | 进程生命周期、事件归一化、去重、状态、授权检查、提交/远程请求、恢复 | 不内置领域推理、不枚举策略树、不假装科研裁判 |

大脑输出经过结构校验的 Decision，控制器执行其中被授权的动作。Prime 的工具循环和子代理机制保留上游实现。大脑和 Prime 可以读取各自 scratch 与证据快照；科学代码只有 Prime 在本轮工作目录中修改。

大脑可自由研究资料和审阅证据，不需要逐步命令 Prime。其本地原生工具只能用于文件/编排任务，科学计算依然通过 Bohrium。

## 运行单位

`Challenge` 是带版本的题目。`Run` 是一次有预算、有配置快照的研究会话。`Trial` 是 Run 内可比较的一轮假设/方案实验，可能包含多个远程 Job。`Submission` 对应平台的一次 Attempt；并非每个 Trial 都需要提交。

更换模型、经验快照或核心方案，创建新的 Trial 或新的 Run，并记录父关系。相同 Trial 不静默热换模型。已有最佳合法产物保持不可覆盖，后续试验使用独立目录。

## 完整闭环

题目快照 → 大脑形成研究目标 → Prime 执行一轮 → 远程 Job 产生证据 → 大脑审查 → 继续/换路/提交 → 记录经验。

Prime 通过项目级、可导入的 Python skill 调用本系统受限 API，例如 `submit_job(spec)`、`job_status(id)`、`checkpoint(report)`、`propose_experience(draft)`。这些是**本项目待实现接口**，不是 Prime 已有函数。不要伪造上游包导入路径。

skill 的后端作用域只允许本 Run；凭据为短时能力令牌，不是 Playground/Bohrium 的真实密钥。代码目录、输出目录及已有 Job ID 由控制器绑定，Prime 不能操作其他 Run。

大文件保持远程引用及 hash；下载仅限有用证据/提交所需文件。统计、拟合、重绘等分析脚本仍远程执行。读取远程结果 JSON、整理文件清单、校验文件 hash 属于本地结果管理。

### Bohrium-first 的实际限制

Prime 的通用 IPython 可以执行任意 Python；仅靠提示词不能构成“绝无本地科学计算”的强隔离。本版本使用无科学依赖的轻量执行环境、只暴露编排 skill、轨迹检查与文件权限降低绕过，并将科学产物的 Bohrium Job 来源作为验收条件。不得把这种部署声称为安全沙箱。

发现本地生成科学结果就标记该 Trial 的来源不合格并在远程重做；不悄悄接受本地结果。需要强隔离时，必须额外核实并部署远程执行环境，此项不假装已经具备。应用开发测试、协议假服务和前端构建不受科学计算限制。

## 什么时候唤醒大脑

| 事件 | 行为 |
|---|---|
| Run 开始、用户新指导 | 立即安排一次判断 |
| 一轮实验完成、阻塞、高成本资源申请、官方评分变化 | 合并相关证据后安排判断 |
| 心跳、普通日志、重复状态、尚在正常运行的 Job | 控制器处理，不调用大脑 |

每个 Run 同时最多一个大脑判断。判断期间积累事件，在其结束后合并处理。Decision 携带观察到的 `state_version`；版本已因用户暂停/新目标等关键变更而变化时，保存旧判断但不执行其中变更动作。日志字符增量不提高此版本，避免无意义失效。

远程轮询采用可配置间隔与退避，尊重 Retry-After；用户可手动刷新。没有新证据时大脑输出 wait，不能自我触发无限循环。达到本轮判断次数或时间上限就暂停并显示原因。

## 运行状态与暂停

Run 生命周期：`created → running → pausing → paused`，可进入 `blocked / recovering / finished / failed / cancelled`。`blocked` 必须带可读原因与恢复条件。

“暂停研究”立即禁止新的模型 turn、Job 和提交；请求代理在安全边界停止，现有远程 Job 默认继续并明确显示可能继续计费。只有代理确认已停才显示 paused。超时显示 pausing/需要处理，不伪造成功。

“终止研究”中止代理会话；已有 Job 是否取消由用户选择，控制器逐个发送 bohr 取消请求并核实状态。取消失败、取消结果未知与已取消分别显示。终止不会删除证据或历史 Attempt。

Prime `steer` 的接受不等于已生效；前端显示 queued/confirmed/unknown。没有上游可核对的消费标记时，不显示“已执行”。Prime 的 abort 也不代表远程 Job 已停止。[S1]

## 持久化与恢复

SQLite 是 Run 状态与规范化事件的唯一权威源；不要再维护另一份可独立写入的 `events.jsonl`。JSONL 只作为导出。关键状态更新与事件追加在同一事务提交，SSE 从数据库序号续传。

后端单进程、单 worker；启动使用工作区锁，第二个控制器拒绝接管同一数据目录。浏览器只订阅，不拥有运行生命周期。stdout/stderr 持续消费，输出大小有界；不因前端断连堵住代理进程。

重启先标记 recovering，读取已记录的 Job ID/Attempt ID、待完成外部操作和运行快照，查询远程状态。已有 Job 继续挂接，不再提交一次。CLI 会话支持恢复时恢复对话，但 IPython 的 Python 对象/变量不得视为已恢复；从保存代码和 checkpoint 重建最少本地状态，禁止自动重做已完成科研计算。

无法确认子进程归属时不能只凭 PID 杀进程。只管理本应用启动且身份匹配的进程；未知遗留会话显示待核对，先禁止新写操作。

## 两段提交和不确定性

本系统在外部操作前写操作日志：唯一 `operation_id`、Run/Trial、请求摘要、payload hash、授权 ID。创建 Attempt 成功后立即保存平台 ID，再上传固定 hash 的 bundle。[S6]

超时之后的语义是“结果未知”，不直接重试非幂等 POST。可按已知 ID 查询；创建响应丢失则按平台已支持的字段/列表对账。只有经文档和实测证实支持幂等键才能发送并依赖它；无法核对时暂停该提交并请求人工确认。HTTP 客户端默认只自动重试安全读取。

评分状态和 Run 状态独立。没有查到终态分数就保持等待/未知。`practice`、`post_deadline`、`late_scored` 等若存在则保留，资格未知不能算入比赛成绩。具体字段以实际版本为准。

## 预算与权限

Run 授权绑定题目、模型 Profile、资源范围、期限、最大 Job 数/运行时长、最大模型调用或 turn 数、最大 Attempt 数。控制器在新操作前检查，并保守记录尚在执行的费用预留。模型原生内部调用不全部经过本系统，若上游不暴露逐调用拦截，相关额度只可作为尽力停止边界；真实强限额需供应商/平台侧支持，UI 明示保障级别。

Prime 子代理默认禁用；实测能限制和汇总其用量后才可在授权范围内启用。不能只统计根代理费用。计价缺失用 unknown，不能把上游自定义模型默认零价格当作免费。[S2]

任何暂停/超额只承诺禁止新增受控操作；已发出的模型请求和远程 Job 仍可能产生费用。科学资源预算以用户授权和平台限制为准，不内置猜测价格。

## 配置与安全

后端只绑定 `127.0.0.1`，校验 Host/Origin；写请求要求本地会话认证与 CSRF 防护。第一次启动产生本地配对码，浏览器换取 HttpOnly、SameSite 严格的会话 cookie；配对码不放 URL 查询串/浏览器存储。首版不开放公网服务。

配置文件仅保存非秘密 Profile 和 SecretRef。密钥优先存系统凭据服务；无可用服务时，保存为权限 0600 的本地 secrets 文件并明确显示“本机明文保存”，允许只从环境变量读取。不得自创加密并把密钥放同目录冒充安全。

各子进程使用环境 allowlist：Prime 只拿它自己的模型凭据与 Run 能力令牌；bohr 子进程才拿 Bohrium key；大脑只拿原生登录/自用模型权限。用户已有的 Codex/Kimi 登录数据不复制进项目或提交包。

模型 API Base URL 可以配置 HTTPS 或用户明确配置的 loopback HTTP。配置保存不能顺便访问地址；测试连接需显式动作。转跳不携带认证至新 origin。题面、论文、经验、日志视为不可信输入，不能覆盖授权与路径限制。

提交包采用允许清单、固定清单与 hash；不打包整个工作区。排除配置密钥、会话认证、无关日志和其他题目数据；拒绝路径穿越和越界符号链接。Trace 是否需要提交只按已核实规则决定，需脱敏且不伪造内部推理。
