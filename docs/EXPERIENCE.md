# 可编辑经验：两种作用域，一条证据链

## 文件是用户编辑界面

当前经验保存在 `experience/global/*.md` 与 `experience/challenges/<challenge_id>/*.md`。使用 YAML frontmatter + Markdown 正文。前端编辑同一份文件；用户也可以用文本编辑器修改。

SQLite 保存不可覆盖的修订历史和检索索引，当前有效文本以通过校验的 Markdown 文件为准。不要另建不透明向量数据库作为首版权威源。空经验库可用，不预装未经验证的“获胜秘诀”。

| 字段 | 语义 |
|---|---|
| id / title | 稳定标识和可读标题 |
| scope / challenge_id | global 或 challenge；后者必须与目录对应 |
| status | candidate / active / retired；代表是否参与默认检索 |
| evidence_status | hypothesis / observed / validated / contradicted；与是否启用独立 |
| kind | heuristic / procedure / failure / platform |
| tags / applicability | 检索标签和适用条件 |
| evidence_refs | 具体 Trial、Job、文件 hash、官方文档或反馈引用 |
| expires_at | 可选；平台/评分规则类经验建议有失效复核时间 |

revision hash、操作者、前驱、写入时间由系统维护，不能靠用户改一个 frontmatter 字段伪造。模板位于 `templates/experience.md`。

正文回答“什么条件下做什么、有什么证据、什么时候不适用”。允许记录有用但尚未验证的假设；必须显示 hypothesis，不能在标题中悄悄变成事实。

## 自动积累与用户编辑（2026-09-18 闭环版）

大脑在生命周期审阅的 Decision 中通过 `experience_proposals` 写经验，后端只忠实落库，不做语义审查：

- **题内提议（scope=challenge）直接落 active**，即时生效，无需 promote_experience。
- **全局提议（scope=global）落 candidate**，唯一晋升通道是用户在前端经验页批准/驳回（驳回附批注 `review_note`，大脑下轮整理时参考重写或放弃）。大脑对全局 active 条目的 target_id 更新会落新修订但状态回 candidate，待用户复核。
- proposal 带可选 `target_id` 表示更新已有条目：冲突语义=追加新修订，永不拒绝；大脑先读库再决定新建/更新/不变，同主题不重复造条目。kind 可由大脑指定，缺省 heuristic。
- **触发**：Run 收尾（finish）自动推迟为一轮 curation 生命周期审阅——素材含本题全部经验正文节选与逐条使用-结果回联（usage），审阅完结后自动终态；额度用尽则跳过直接收尾，防死锁。全局整理由用户在前端手动触发（无 Run 的一次性大脑会话），素材含全局条目（含待审批与驳回批注）+ 入选题目的题内经验与回联。
- **效果回联**：Run 起止各记一份 active 经验版本清单（runs.experience_snapshot），提交分数本就连着 run_id；usage 统计精确到题目粒度，只在整理/选择经验时给大脑看，平时帧不带。无任何自动评分规则，判断归大脑。

用户可编辑、停用、回滚任何经验。修改建议/结论的修订重新评估 evidence_status；不得继承旧版本 validated 标签。

UI 显示“当前可用版本”和“本轮实际使用版本”。编辑后默认下一 Trial 生效；当前 Trial 使用冻结快照。用户可以另发一条指导或暂停，不静默重写正在执行的上下文。

### 全局晋升

| 候选内容 | 允许的处理 |
|---|---|
| 某题一次得到较好得分的参数 | 留在题目内，不能泛化为全局最优 |
| 有独立复现支撑、跨问题适用条件明确的方法 | 可晋升带范围的全局经验，引用原题证据 |
| 平台接口/提交规则 | 官方文档与实际响应支撑后激活，绑定版本/时间；不要求伪造跨题实验 |
| 失败/被否决路线 | 保留触发条件、失败证据及重试条件；不是永远不可再试 |

独立复现指新的一次实际验证，不是两个模型复述同一份总结。晋升不会把原题目记录移走；新增一个 global 条目，保留 `derived_from` 链接与原始失败记录。

## 保留负经验

失败修订、被否决的策略/skill、失败原因、当时配置、证据和后续结果必须可查。后来成功也不能删去当时失败的事实；追加说明新条件为什么改变结论。

检索要能提醒重复失败，但只在条件匹配时生效。“某环境安装失败”不能提升成“此方法科学上无效”。科学失效、运行错误、提交错误和评分器异常分别记录。

## 编辑一致性与恢复

每次 UI 保存附 `base_revision_hash`；当前文件 hash 不匹配返回 409 与新旧内容，用户选择合并，不允许后台覆盖外部编辑。创建/编辑都做路径、frontmatter、scope 与证据引用格式验证。

后端单写锁下记录旧内容和拟写内容的修订日志，再原子替换 Markdown 文件，最后标记修订应用完成。启动时核对未完成的写入与实际文件 hash，恢复或标记冲突；不能声称数据库事务同时原子提交了文件系统。

外部编辑在启动、显式刷新和新 Trial 前扫描；有效变更导入历史后更新索引。无效 frontmatter 不删除文件，显示校验错误并保留上一份已认可版本；新 Trial 前让用户清楚知道被排除的编辑。首版不需要全盘实时文件监听。

“回滚”创建新修订指向旧内容，不抹掉中间历史。“删除”默认退役，历史仍存在；导出不包含凭据。

## 检索与快照

首版使用作用域筛选、明确标签/关键词和简单排序，不引入 embedding 服务。先筛掉 retired、过期或不适用的经验；再选相关全局规则、当前题目最近有效观察和匹配失败证据。用户固定的条目优先，但不得越过输入预算。

可配置数量和字符/Token 预算，默认只带少量完整条目及可按需展开的索引。不把每轮 Trace 全量带入，不让长期记忆无限增长上下文。

Trial 开始时生成不可变 `memory_manifest`：经验 ID、revision hash、scope、evidence_status、title（入选理由与注入正文 hash 未实现，留债）。

执行器不接收经验正文注入：Trial 任务文本给出经验库目录，提示词要求开工前自读 global/ 与本题目录下 status=active 的条目；运行中经验更新由大脑在指导里告知。经验是可质疑的输入，不能变更预算、读其他秘密、安装未批准 skill 或覆盖系统边界。用户意图/题面与经验冲突时记录冲突，不能悄悄让旧经验压过新证据。

## 经验与 skills

经验描述条件和判断；skill 是可执行代码及使用说明。重复有效且能测试的 procedure 才成为 skill 候选。自动编辑经验不能自动安装或执行代码。运行中不热修改 skill，失败版本及其测试证据保留。
