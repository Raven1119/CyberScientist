# 可编辑经验：两种作用域，一条证据链

## 文件是用户编辑界面

当前经验保存在 `experience/global/*.md` 与 `experience/challenges/<challenge_id>/*.md`。使用 YAML frontmatter + Markdown 正文。前端编辑同一份文件；用户也可以用文本编辑器修改。

SQLite 保存不可覆盖的修订历史和检索索引，当前有效文本以通过校验的 Markdown 文件为准。不要另建不透明向量数据库作为首版权威源。空经验库可用，不预装未经验证的“获胜秘诀”。

| 字段 | 语义 |
|---|---|
| id / title | 稳定标识和可读标题 |
| scope / challenge_id | global 或 challenge；后者必须与目录对应 |
| status | candidate / active / retired；代表是否参与默认检索 |
| evidence_status | hypothesis / observed / validated / contradicted；与是否启用独立 |
| kind | heuristic / procedure / failure / platform / environment / strategy |
| audience | brain / executor / both；旧条目缺省为 both |
| tags / applicability | 检索标签和适用条件 |
| evidence_refs | 具体 Trial、Job、文件 hash、官方文档或反馈引用 |
| expires_at | 可选；平台/评分规则类经验建议有失效复核时间 |

revision hash、操作者、前驱、写入时间由系统维护，不能靠用户改一个 frontmatter 字段伪造。模板位于 `templates/experience.md`。

正文回答“什么条件下做什么、有什么证据、什么时候不适用”。允许记录有用但尚未验证的假设；必须显示 hypothesis，不能在标题中悄悄变成事实。

## 自动积累与用户编辑（2026-09-18 闭环版）

大脑在生命周期审阅的 Decision 中通过 `experience_proposals` 写经验，后端只忠实落库，不做语义审查：

- **题内提议（scope=challenge）直接落 active**，即时生效，无需 promote_experience。
- **全局提议（scope=global）落 candidate**，唯一晋升通道是用户在前端经验页批准/驳回（驳回附批注 `review_note`，大脑下轮整理时参考重写或放弃）。大脑对全局 active 条目的 target_id 更新会落新修订但状态回 candidate，待用户复核。
- proposal 带可选 `target_id` 表示更新已有条目：冲突语义=追加新修订，永不拒绝；大脑先读库再决定新建/更新/不变，同主题不重复造条目。kind 可由大脑指定，缺省 heuristic。
- **触发**：所有 Run 结束先成为终态，再排独立新会话整理及复盘；两种维护合计最多两次模型调用，不消耗科研审阅次数。整理失败仍收尾，已开始但未知的调用不重发。全局整理由用户在前端手动触发（无 Run 的一次性大脑会话），素材含全局条目（含待审批与驳回批注）+ 入选题目的题内经验与回联。
- **效果回联**：Run 起止各记一份 active 经验版本清单（runs.experience_snapshot），提交分数本就连着 run_id；usage 统计精确到题目粒度，只在整理/选择经验时给大脑看，平时帧不带。无任何自动评分规则，判断归大脑。

用户可编辑、停用、回滚普通经验。`environment` 只由代码依据已登记的真实回执事件生成和刷新，用户与代理不能编辑、审批或回滚；修改建议/结论的修订重新评估 evidence_status，不得继承旧版本 validated 标签。

UI 显示“当前可用版本”和“本轮实际使用版本”。编辑后默认下一 Trial 生效；当前 Trial 使用冻结快照。用户可以另发一条指导或暂停，不静默重写正在执行的上下文。

### 全局晋升

| 候选内容 | 允许的处理 |
|---|---|
| 某题一次得到较好得分的参数 | 留在题目内，不能泛化为全局最优 |
| 有独立复现支撑、跨问题适用条件明确的方法 | 可晋升带范围的全局经验，引用原题证据 |
| 平台接口/提交规则 | 官方文档与实际响应支撑后激活，绑定版本/时间；不要求伪造跨题实验 |
| 失败/被否决路线 | 保留触发条件、失败证据及重试条件；不是永远不可再试 |

独立复现指新的一次实际验证，不是两个模型复述同一份总结。晋升不会把原题目记录移走；新增一个 global 条目，保留 `derived_from` 链接与原始失败记录。

## 保留负经验

失败修订、被否决的策略/skill、失败原因、当时配置、证据和后续结果必须可查。后来成功也不能删去当时失败的事实；追加说明新条件为什么改变结论。

检索要能提醒重复失败，但只在条件匹配时生效。“某环境安装失败”不能提升成“此方法科学上无效”。科学失效、运行错误、提交错误和评分器异常分别记录。

## 编辑一致性与恢复

每次 UI 保存附 `base_revision_hash`；当前文件 hash 不匹配返回 409 与新旧内容，用户选择合并，不允许后台覆盖外部编辑。创建/编辑都做路径、frontmatter、scope 与证据引用格式验证。

后端单写锁下记录旧内容和拟写内容的修订日志，再原子替换 Markdown 文件，最后标记修订应用完成。启动时核对未完成的写入与实际文件 hash，恢复或标记冲突；不能声称数据库事务同时原子提交了文件系统。

外部编辑在启动、显式刷新和新 Trial 前扫描；有效变更导入历史后更新索引。无效 frontmatter 不删除文件，显示校验错误并保留上一份已认可版本；新 Trial 前让用户清楚知道被排除的编辑。首版不需要全盘实时文件监听。

“回滚”创建新修订指向旧内容，不抹掉中间历史。“删除”默认退役，历史仍存在；导出不包含凭据。

## 检索与快照

首版使用作用域筛选、明确标签/关键词和简单排序，不引入 embedding 服务。先筛掉 retired、过期或不适用的经验；再选相关全局规则、当前题目最近有效观察和匹配失败证据。用户固定的条目优先，但不得越过输入预算。

可配置数量和字符/Token 预算，默认只带少量完整条目及可按需展开的索引。不把每轮 Trace 全量带入，不让长期记忆无限增长上下文。

Trial 开始时生成不可变 `memory_manifest`：经验 ID、revision hash、scope、evidence_status、title（入选理由与注入正文 hash 未实现，留债）。

大脑的帧和清单只冻结 `brain`/`both`，执行器 Trial 任务只冻结 `executor`/`both`；旧条目按 `both`。执行器任务文本包含该冻结清单和经验库目录，可按需读取；不应把未投递角色的条目当作任务输入。运行中经验更新由大脑在指导里告知。经验是可质疑的输入，不能变更预算、读其他秘密、安装未批准 skill 或覆盖系统边界。用户意图/题面与经验冲突时记录冲突，不能悄悄让旧经验压过新证据。

环境事实来自镜像事实、沙箱机器/模板/配额及客户端主机的受控回执，保存 `observed_at`、`source=event:<run>:<seq>` 和默认 7 天的 `recheck_after`。新回执内容有变时追加修订；到期无新回执则转为待复核候选，停止注入。该字段描述观察时的环境，不是长期稳定的平台承诺。

## 经验与 skills

经验描述条件和判断；skill 是可执行代码及使用说明。重复有效且能测试的 procedure 才成为 skill 候选。自动编辑经验不能自动安装或执行代码。运行中不热修改 skill，失败版本及其测试证据保留。

## 2026-09-23：暂停后整理本轮经历

研究页「整理本轮经验」使用独立 CurationResult，输入包含冻结的本 Run 重要公开事件与检查点，并注明外部指导和未知结果。提案的每个证据引用须在本次快照中存在；这验证来源存在，不宣称科学结论或因果收益已经成立。题内经验仍可即时使用，全局仍待用户审批；本次推导强制 hypothesis。用户可查看实际保存数量和失败原因，零条是合法结果。

全局经验页整理仍处理经验库，不冒充指定 Run 复盘。两种整理均不会创建科研 Job 或恢复已暂停 Run；历史失败整理记录保留。

## CS-UP-08：索引、中文相关性和实时读取

默认注入预算为 24,000 字符。每个角色收到当前题内和全局全部有效经验的索引（标题、适用条件、类型、受众、版本）；正文按角色和中文双字片段／技术词相关性排序，索引先占预算。超出正文预算的内容标记截断。过期、退役和未审批的全局候选不默认参与检索。

`research_experience` 的 list/read 只读工具给 PI 与求解者读取最新已登记有效版本；read 单独冻结此次交付，返回 context_id 与 revision_id，可用于真实采用声明。旧 Trial 的上下文仍保留，不静默覆盖。

五份可执行全局配方位于 experience/global/csup08_*.md，均为 candidate/hypothesis，等待用户在前端审批。历史失败与替代步骤的未验证状态写在条目中，不能把配方候选当成成功环境。已核验环境回执由代码生成 environment，不走候选审批。


## CS-UP-09：同题策略交接

每个 Run 的 PI 策略卡是 kind=strategy 的题内经验，稳定 ID 为 strategy_<run_id>。卡片保存路线与理由、与此前路线的区别、失败判断与证据、直接可用的建议；计划保持 hypothesis，正式最佳验证分只由后端可信评分账本补入。PI 首帧完整读取全部同题卡片，并为这次投递冻结独立 experience_context，返回其 ID；采用声明绑定实际交付修订。

开局和普通／生命周期里程碑审阅的可选 research_brief 更新自己的策略卡，实际 Trial 未给简报时按 PI 目标补建最小交接卡。原生 PI 不能通过普通经验提议覆盖另一个 Run 的卡。正式评分提交账本后立即刷新，实时 research_experience 查询返回最新有效修订，不等待下一 Trial。卡片文件冲突或损坏写 strategy.update_unknown，继续既有授权研究，不冒充保存成功。

## CS-UP-09 W4：独立收尾与新上下文复盘

正常结束、用户终止、运行错误、活动授权耗尽和科研审阅额度耗尽都持久排入维护队列。终态与队列原子落库；暂停不等于结束，原生停止和关闭均未知时保持 pausing，并保存维护记录。每个 Run 的整理及复盘合计最多两次原生模型调用，科研额度用完仍可整理；进程中断的已开始调用记 unknown，不自动重发。

Trial 完成声明、正式结束和中断均补记本题关键记录，明确检查点是执行器声明、正式分数来源和验证器版本，保留修订。整理正文先写动作、禁忌、关键数值及配方，再用一两句话说明不确定性并附证据。

复盘使用新只读会话及完整公开事件文件（无逐事件截断；排除原始模型输出及私有笔记），保存文件 SHA 和边界。策略教训为独立 candidate/hypothesis，不覆盖策略卡或现有 active 经验。报告保存系统缺陷、策略候选、代码回执环境事实三部分；模型环境文字不能自动成为事实。完整文件是否被真实模型通读仍需外部验证，报告不凭自述宣称已核实。默认便宜 Codex Sol；W5 再接入可配置提供方。
