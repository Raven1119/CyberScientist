# CyberScientist 经验管理方案

基于代码：`46bba5d0bc24a03ec1be889384442e6dbe36ced2`。这是待实施方案；没有修改生产代码。相关故障及证据见 `AUDIT.md`。

## 1. 系统应学习什么，保留什么架构

### 设计结论

在当前 **Markdown + SQLite + RunController + ObservationFrame + guidance/checkpoint** 上，建立一个能解释“何时采用哪条协作策略、采用哪一版、随后出现什么证据”的闭环。先修正确性，再判断在线学习是否提高科研效率。

**经验单位：带适用边界的科研协作策略。**它可以是可复用的诊断/实验选择方法、证据交接方式、何时咨询或换路，以及附条件的负面经验。原始 Trace 是来源；一次指导是具体应用；经验是可复用但可被新证据修正的策略。

不增加第三个常驻 agent，不改变 Codex/Kimi 原生执行，不引入权重训练、经验价值 RL、分布式图数据库或新 Skill 平台。科学判断仍由大脑与执行器承担。

| 已有模块 | 保留职责 | 需要补齐 |
|---|---|---|
| `experiences.py` | Markdown 编辑、SQLite 历史 | ID 文件名、显式当前/批准版本、外部编辑登记、版本绑定审批 |
| `controller.py` | 生命周期、审阅和指导调度 | 使用统一经验包、记录采用、关联后续结果、正确反馈评分 |
| `observation.py` | 宏观有界证据投影 | 真实覆盖范围、结构化结果、带边界/证据标签的经验视图 |
| `collab.py` | 检查点、指导投递和 ACK | 幂等门禁、经验采用/应用证据关联；ACK 不等于完成 |
| `mailboxes.py` | 提交、评分 | 原子预算、unknown 对账、稳定提交包与结果归属 |
| `ExperiencePage.tsx` | 编辑、审批、历史展示 | 正常创建、显示当前草稿/正在使用的批准版、版本绑定操作 |

### 内容格式：保持少量结构字段，科研内容用 Markdown

保留现有 `scope/status/evidence_status/kind/tags/applicability/evidence_refs`，不扩张成几十种经验类型。正文采用下面的可读格式；模型允许不更新，也允许只修正一个条件。

```markdown
## 适用情境
任务/方法类别、当前异常、已知前提；什么条件下需要考虑这条经验。

## 协作策略
大脑：负责哪项路线或证据判断。
执行器：自主完成哪些实验/诊断，不规定无关工具细节。
交接：应提供哪些足够判断的证据，何时继续、咨询或改变路线。

## 检验与边界
预期改善什么；如何用下一次结果检验；不适用条件和允许重试的变化。

## 依据与反例
支持来源、反例、尚未排除的替代解释；引用原始证据，不复制全部轨迹。
```

“是否启用”和“证据强度”独立。题内 `active + hypothesis` 合法，表示可以有条件试用；`observed` 需要对应事实；`validated` 不来自重复复述。`contradicted` 可以保留为负面提醒，但必须展示反驳状态，不能渲染成没有警告的正面建议。

### 与真实任务的对应

**数值复现类。**仓库 [checks/build_arm_bundle.py](https://github.com/Raven1119/CyberScientist/blob/46bba5d0bc24a03ec1be889384442e6dbe36ced2/checks/build_arm_bundle.py) 记录 Aiyagari 复现误差在部分参数区间集中，网格/容差调整未消除关键失败。可提炼“执行器提供误差分布及已排除因素，大脑选择一个能区分剩余解释的实验”的候选策略。脚本中尚未完成的 Rouwenhorst 消融不能写成已验证修复。

**平台受约束的科研计算。**仓库 [STATUS.md](https://github.com/Raven1119/CyberScientist/blob/46bba5d0bc24a03ec1be889384442e6dbe36ced2/STATUS.md) 记录过工具来源、认证状态和资源配额的误判。适用经验应明确“未安装/未认证/无权限/无配额”是不同状态，并规定交接哪条真实响应。对观测帧漏消息或门禁 bug 直接修代码，不让经验库承担修补控制器的责任。

冷启动从已有真实记录、官方可复现流程和少量明确标注的先验中选取；没有适用项时返回空经验包。后续未验证的新环境不继承原环境的成功等级。

## 2. 最小可实施闭环

### A. 先建立可信的版本底座

**文件身份。**沿用 global/ 与 challenges/<id>/，文件改为 `<experience_id>.md`。ID、作用域和题目归属在普通更新中固定；跨范围推广创建派生条目，保留原题记录。不要依赖标题确定身份。

**版本模型。**保留现有 `experience_revisions`，将其解释为“修订操作历史”。`id` 是独立 revision_id，`revision_hash` 保留为内容哈希；允许同一内容在不同修订操作重复出现，移除把 `(experience_id, revision_hash)` 当作操作唯一性的假设。补 `parent_revision_id`，有重试需要的写入携带 operation_id。回滚产生新操作，内容可复用旧哈希。

仅新增两个小表，避免重新建设存储系统：

| 表 | 最小信息 | 作用 |
|---|---|---|
| `experience_heads` | experience_id、scope/challenge_id、file_path、head_revision_id、active_revision_id | 明确最新草稿和后续决策默认采用的版本 |
| `experience_uses` | use_id、experience_id、revision_id、run/trial/frame/guidance 引用、presented/adopted 记录、result_refs | 将展示、实际采用和后续证据区分开 |

字段形状可沿用现有 JSON 证据引用，首版不拆出额外的收益、角色、轨迹图表。`experience_uses` 的事件变化写入现有 append-only events，表只是便于查询的当前投影；原始事实不被覆盖。

**写入流程。**同一单写保护下检查 base revision，登记待应用修订，原子替换 Markdown，再标记应用并切换 head；新版本只有在文件/修订一致且可用后才能进入新经验包。崩溃恢复对账待应用记录；不声称 SQLite 事务与文件替换天然构成跨系统原子事务。

**全局审批。**题内合法提议按现有政策自动切换 active，但保持原证据状态。全局新候选只更新 head，旧 approved active 保持可用；批准带 expected_revision，比较成功才切 active。首次候选没有 active；明确退役清空 active。界面分别显示“最新草稿”和“已批准可用版”，不再用一个 status 混淆二者。

**外部编辑。**扫描检测到合法新字节，先追加 external 修订；全局外部编辑形成待批准候选，除非用户通过明确审批操作激活。非法编辑留在编辑界面并报错，继续提供此前可用版。外部修改不能静默改写已冻结的 Trial 输入。

**迁移。**备份原库与文件后，从实际字节与已存修订重建确定的指针。已覆盖条目只能依据可恢复记录恢复；无法确定的身份、先后与采用情况标为 unknown。旧 manifest 保留，旧 usage 改标“当时清单/相关 Run”，不能升级为实际采用记录。

### B. 同一来源，按角色提供有界经验包

新增一个小型 `experience_context.py`，集中完成候选获取、边界元数据、预算及冻结渲染；不要再把三套选择逻辑分别放在 controller、observation 和执行器自由读目录中。

机械筛选只处理作用域、可用版本、退役、可确定的结构化时间/环境约束及输入预算；自由文本中的科研适用性交给模型判断。候选可用当前目标/方法关键词和现有 tags 做轻量匹配；相关性较难判断时给大脑少量候选，允许明确不采用。过期的正面规则不默认注入；反例和被反驳条目仅以带状态的警告/反证角色进入。这里不加入自动科学结论评分器。

每次在 Trial 创建或明确的新指导边界冻结实际正文：

```json
{
  "experience_id": "exp_numeric_diagnosis",
  "revision_id": "rev_...",
  "content_hash": "sha256:...",
  "scope": "challenge",
  "evidence_status": "hypothesis",
  "applicability": "数值误差在某参数区域集中，精度加密收益有限",
  "selection_reason": "匹配当前诊断决策",
  "brain_view": "比较剩余解释，选一个有区分力的验证",
  "executor_view": "交付误差分布和已排除因素，自主实现最小对照",
  "evidence_refs": ["checkpoint:..."]
}
```

上述 role view 是同一经验版本的投影，不是两套独立维护的规则；冻结包还保存最终传给模型的文本及哈希。`memory_manifest.json` 扩展为包索引，指向不可变内容，而非实时文件名。审阅帧通过同一服务获得正文、来源和状态；执行器任务直接获得选定内容或确定的冻结文件路径。

统一执行 `max_injected_characters` 等现有配置，并保留省略数量/理由；不让六条全局条目必然排挤所有题内经验。相关经验稀少时不补无关条目。大脑看选择理由、边界与反例，执行器看可操作的策略和交接证据，继续保留局部自主权。

### C. 采用、结果与增量整理

**展示不算采用。**包交付时登记 presented。大脑在 Decision/Guidance 中引用实际用于选择路线的经验修订；执行器在 checkpoint 中声明采用、质疑或不适用，并附对应行动证据。复用既有协议，增加可选 `experience_uses`/`experience_refs` 字段，不新增常驻角色。

**采用不算有效。**将 use_id 接到现有 `guidance_id → expected_change_md → checkpoint/result_refs` 链。ACK 只表示收到/接受指导；完成证据来自后续检查点、测试、Job 或提交结果。仅有模型声明时明确标 `reported`，未取得证据保持 unknown。多个动作同时变化时保留混杂说明，不给单条经验凭空分配收益。

**结果要定位到当时的行为。**正式评分读自 submissions，关联具体提交、Trial 和冻结包/代码产物哈希。经验效果优先查看“采用后是否避免重复错误、是否产生有区分力的实验、是否满足原成功判据”，Run 最高分只作背景。能否解释因果改善须靠对照，不能从相关性自动推导。

**自然节点更新。**在现有大脑审阅处，把新近已完成的采用记录与结果作为增量材料；稳定修复、可靠反例、假设被证伪或任务完成才触发整理，不对每个工具调用都反思。模型可以新建、修订、缩小适用范围、追加反例或不变。大脑能定位到所引用的原始材料；压缩帧不足时按引用补必要证据，不把全部原始轨迹塞回主上下文。

**不只依赖 finish。**目前预算耗尽/取消路径可能没有正常收尾。新证据先被动留痕，未整理项记录待处理；暂停或终止后不再自动启动付费整理，下一次获得授权时处理。迟到评分同样只登记待处理事实。

**失败的分流。**科学假设未获支持可形成有用反例；工程失败、资源不可用、提交异常和评分未知分别保留来源，不互相泛化。B01–B21 这类确定程序 bug 的主要归宿是修复与测试；只有可迁移的诊断/协作判断才进入经验库。

### 冷启动与效率原则

优先使用已有证据而非重新跑昂贵完整任务。数值诊断经验采用一个能区分候选解释的最小实验验证；只有验证支持时扩大适用范围。初始经验数量由任务相关性和上下文预算决定，不预设几十条“科研通用原则”。在不同模型/运行时之间迁移时保留环境信息，能力不匹配就降低建议细节或声明不适用。

检索和整理先用现有模型的判断与小范围上下文完成。只有实际测出选择成本/质量瓶颈后，才考虑 embedding 或经验效用排序；没有实际采用数据前不训练经验价值模型。

## 3. 验证与交付边界

### 一个最小垂直切片

选一个可复现的科研诊断场景，第一轮生成一条带真实证据的题内经验；第二轮获得它的冻结版本并明确采用，产生结果后引用 use_id 回联。中途编辑/回滚不改变已交付包；全局推广需要用户批准正在展示的那一版。整个流程在既有两角色和前端内完成。

### 三个完整阶段

| 阶段 | 完整交付 | 必须看到的结果 |
|---|---|---|
| 可信保存和运行 | 修复覆盖/版本/审批；恢复正确门禁、模式授权、提交预占和 unknown 语义 | 数据与控制故障回归通过，未授权不会产生真实副作用 |
| 一次可信复用 | 统一冻结包、采用记录、事件覆盖和评分入帧 | 两轮之间能追到同一经验修订、实际行动和后续结果 |
| 持续增量学习 | 在现有审阅中消费增量结果、保留反例和待整理项 | 等预算对照中，在线更新对后续任务产生可测额外收益 |

不将每个字段拆成独立任务卡；每阶段交付可运行路径和针对性的回归证据。

### 学习效果比较

先修复影响数据与控制正确性的 bug，再比较以下三组；不能让有经验组同时受益于额外程序修复。

| 组别 | 经验条件 | 回答的问题 |
|---|---|---|
| A | 不使用经验，模型与工具链相同 | 修复后的能力基线 |
| B | 固定、带来源的初始经验 | 冷启动材料是否有帮助 |
| C | 与 B 相同的初始经验，允许增量更新 | 持续学习是否额外提高效率 |

按时间隔离训练/提炼与后续验证材料，在相同模型和总预算下比较：首轮有效实验/交付表现、到达有效证据所需模型与计算成本、重复失败次数、对后续不同实例的迁移。检索、整理和验证成本均计入；不得把后来的成功经验倒灌早期对照。先做小规模可复现对照，不把少数演示结果包装成稳定胜率。

**成功标准：系统能证明某条经验以确定版本影响了一次后续协作决策，并积累支持或反驳它的新证据；再用对照证明这种更新提升了科研结果或效率。**
