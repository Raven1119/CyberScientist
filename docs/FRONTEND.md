# 前端交付规格

## 目标与结构

做一个操作者能日常使用的研究控制台，不做堆满日志的终端替代品。界面中文优先，保留 API、Job、Trial 等必要术语。仅三个主入口：**研究工作台 / 经验库 / 连接与设置**。题目选择与历史 Run 放在研究工作台内部，不为每种实体增加主导航。

`prototype/index.html` 是布局和交互参考，能切换页面、模拟控制、编辑示例经验和保存非秘密配置草稿。其演示数据和模拟逻辑不得复制为生产结果，最终 React 页面必须调用真实后端。

## 研究工作台

顶部是当前题目、赛季/练习身份、契约状态、最新状态更新时间。主要动作只有开始/暂停、发送指导、终止；提交放在单独的结果面板，避免误触。

主区域按“当前意图 → 最近证据 → 下一步”组织。大脑与 Prime 的行为按角色分开显示；用户一眼能看出正在思考、远程计算还是等评分。原始协议和长日志折叠在详情，不把每个 token 都当作研究进展。

| 区域 | 必须展示 |
|---|---|
| 结果概览 | 最高有效官方分数或“尚无有效评分”；来源、资格与更新时间；禁止把 null 显示为 0 |
| 研究状态 | 当前假设、下一步实验、阻塞原因、最近一次大脑介入与证据引用 |
| 活动面板 | 事件流、Trial/Job、产物与提交三个局部标签 |
| 右侧运行摘要 | 大脑和 Prime 配置版本、经验快照、预算/已知费用/未知费用、允许资源 |

导入题目支持 URL/ID，后端验证 origin 和解析结果。展示“缺少评分契约”等具体原因；不可用按钮旁显示解除条件。Demo 使用虚构题目和 DEMO_* ID，不混入真实题库。

### 控制语义

| 用户动作 | UI 反馈 |
|---|---|
| 开始 | 打开预检与本轮授权确认；未配置/未授权时不能开始真实运行 |
| 指导 | 显示“已排队”；可核对消费时才改为已生效，否则保持未知 |
| 暂停研究 | “正在暂停；已有远程任务可能继续运行/计费”；确认代理停下后才显示已暂停 |
| 恢复 | 先核对进程、Job、提交与快照，不能直接从头重跑 |
| 终止 | 明确选择是否一并申请取消远程 Job；保留证据，展示取消结果 |
| 提交 | 先展示文件清单、hash、资格、目标题目和会消耗的提交次数，再按已有授权执行 |

提交面板把“本地准备 / 创建 Attempt / 上传 / 等评分 / 已评分 / 资格”分别显示。不依赖前端计时推断成功。等待过久时展示最近查询结果和时间，而非自动重试创建 Attempt。

## 经验库

左侧为搜索、全局/当前题目筛选和条目列表；右侧为正文编辑、元数据与修订历史。默认展示人可读 Markdown，提供源码编辑，不强制用户填写大量内部字段。

编辑器最少支持标题、作用域、状态、适用条件、Markdown 正文、证据引用；显示 evidence_status，不能用一个“已验证”勾选框制造证据。保存需携带 base hash；冲突时对照展示当前版本和用户草稿，不覆盖任何一方。

历史面板展示操作者、时间、修改原因和差异，可回滚为新版本。停用保留历史。保存成功文案为“已保存，下一轮实验生效”；当前 Run 仍显示原快照。用户手动编辑文件后点击刷新能看到变更或校验错误。

## 连接与设置

| 配置卡 | 基本字段与交互 |
|---|---|
| 大脑 | Codex/Kimi 选择、可执行文件检测、原生登录状态、所选模型、可选受支持供应商配置 |
| Prime 模型 | Provider 标签、具体协议、Base URL、模型 ID、API Key、可选 reasoning 与上下文上限；兼容开关在高级区 |
| 玻尔 | Playground Base URL 与独立 Token；Bohrium AccessKey、项目 ID、bohr 检测与默认允许资源 |

字段旁解释凭据用途：Playground Token 用于竞赛数据/提交，Bohrium key 用于计算，Prime key 用于其模型调用。不要通过一个“Bohrium API”输入框把三者覆盖。

API Key 输入框保存后清空，只展示“已配置/未配置/已过期”，不提供读取明文 API。设置导出永远排除密钥。浏览器 localStorage 不保存真实密钥；原型也不保存用户输入的测试密钥。

“检查安装/配置”不调用付费模型；“测试模型工具调用”明确标明消耗额度且需显式同意。状态包括未配置、未测试、成功、失败、未知；成功时带测试类型和时间。大脑原生登录成功不能连带把 Prime 标为已连接。

## 视觉与可访问性

桌面以 1440px 为主要验收尺寸，平板/窄屏折叠侧栏与右侧摘要，至少保证 390px 下无横向整页溢出。轻量中性色、清晰层级、稳定状态标签；不使用夸张动画、渐变宇宙背景或不反映数据的图表。

原生表单 label、键盘焦点、可关闭对话框、合理对比度必须具备。状态除颜色外提供文字。日志采用等宽字体，正文采用系统字体。新增事件不强迫滚动正在阅读历史的用户；提供“回到最新”。

## 空状态与错误状态

没有连接时解释缺哪个配置；没有题目时提供导入入口；没有评分时显示空值；连接中断显示最后确认时间和重连状态。所有 Demo 页面有固定标签。后端报错显示用户可理解的原因和详情引用，禁止泄漏凭据或内部绝对路径。

至少用浏览器自动化验证主流程、经验编辑冲突和页面刷新恢复。真实集成与 Demo 截图必须分目录保存。
