## FigQA 404 与处理

用户明确更正：FigQA-0177、FigQA-0178 已从平台下架，公开 GET 返回404。因此此前提交404是题目不存在，不是上传或提交协议缺陷。三个 FigQA Run 仍按原计划科研、本地正式评分和策略交接，均不提交；提交、出分和自动收割验证只用 ABC。没有启用可选的第五个旧题 Run。

按用户额外要求，所有真实提交在 POST 前先只读确认平台题目仍存在；404 明确提示“题目已下架或不存在”。未知题目状态不发送。存在性、结束事实和冻结目标授权分别核对，不能用本地缓存题面证明当前参赛资格。

1. 首次 xhigh 分诊180秒超时，按退避重试；仅分诊临时选 low，所有 Run 授权前恢复 xhigh。私有验证脚本误用 `/append` 导致405，未创建额外 Run；改用已有同题追加接口。
2. 第一只 Flash 题目 PI 把 work_package 放在顶层，结构校验拒绝后，原停滞审阅约五分钟自行恢复并启动 Trial。安全暂停后补无损归一到 research_brief；冲突不覆盖，首次拒绝和自动恢复证据保留。
3. 长暂停后，三个原 PI 会话已被原生 CLI 归档，重启恢复返回明确的 -32600 归档错误。真实失败、Trial 中断及维护调用保留。零模型探针验证取消归档后可恢复同一 ID／模型／强度；适配器只在明确归档错误下取消归档一次，再用原参数恢复。没有替换会话或改全局配置。
4. 原三个 Run 仅在既有授权剩余时长内恢复，先一致性备份，保留失败事件、初始快照和部署版本。没有重置计算、提交或维护额度。第四只 Run 在每次施工前同样安全暂停。
5. ABC 首次包上传被明确标为 draft/incomplete：artifacts 写成字符串、expected_outputs 缺 type。这个问题与 FigQA404无关。原生求解者自行修正 manifest；建设助手没有改科学产物。建议性预检增加实际公开 ARM schema 的已观察结构事实，不冒充完整 schema 验证。

7. 旧轮次结束加72小时的停止规则会挡住刚提交的旧题新包，现按新提交时刻保留七天查分；轮内提交仍用原规则。评分确认仍要求至少600秒的两次同值观察，没有把确认时间设为0。

四个Run均finished；ABC因授权到期结束，其余完成科研流程。实际Job共8个：5 Finished、2 Failed、1 unknown。最后安全关机检查can_shutdown=true／错误0／本地原生租约0／未关闭本卡沙箱0，随后停止独立后端；远端unknown Job不因本地关闭而消失。真实科研所用最后版本为b0d9bee，随后时长补修仅经应用测试。
