## 科学评分：W3

71 条轮次内历史记录带 `harbor_score`、`trace_score`，分布在 7 道题。58 条同时有展示分，13 条展示分缺失且回执的 `scoreIsFinal=false`。以下 30–70 轨迹因子公式是主办方告知、由用户转述并写入任务卡的规则，不是从这批分数拟合出的规则：

`harbor_score × clamp((trace_score − 30) / 40, 0, 1)`

在 58 条完整记录中，有 30 条仅与该公式吻合，18 条同时与该公式及 `harbor_score × clamp(trace_score / 100, 0, 1)` 吻合，另 10 条仅与后者吻合（绝对误差阈值 0.001）。只用任务卡公式的最大绝对误差为 20.758，平均绝对误差为 2.520；10 条不吻合记录均有最终分且 `overrideInEffect=false`。它们不能直接归因于覆盖或赛后复评。轮次外那条历史双分项单独保留，不参与上述统计。

补充的**冲突数据的样本内描述**：沿用主办方告知的 70 分界，但把 `trace_score < 70` 的展示分改按 `harbor_score × trace_score / 100` 计算，其余按告知公式计算，58/58 条均在 0.001 内，最大绝对误差约 0.000048。10 条能区分乘法公式的记录，轨迹分在 39–69；30 条能区分告知公式的记录，在 75.925–98.75。其余 18 条的科学分均为 0，不能区分公式。**这 10 条与主办方告知的 30–70 规则冲突**；它们与其余记录同属第 4 季第 9 轮，跨 3 个账号及多个题目，均无可见覆盖，不能简单归因于另一赛季或某个邮箱。可区分样本在 `(69, 75.925)` 没有观测值，因而样本本身不能独立验证 70 分界，也不能解释冲突的原因。上述替代计算只是对同一批历史分数的事后解释，未获平台确认为规则，不能代替从科学文件预测 `harbor_score` 或从轨迹预测 `trace_score` 的评分器。

71 条实时回执还同时给出 `harbor_reward` 与 `harbor_score`：逐条核查均精确满足 `harbor_score = 100 × harbor_reward`（最大绝对误差 0），且 `harbor_replay_executed` 字段均为 1。这只复刻了回执中**奖励值到百分制分数**的换算；奖励值如何由科学产物产生，仍没有输入文件可检验。

## 轨迹评分：W4 预登记

以下假设在分析轨迹分与特征关系前登记；缺少实时组的轨迹内容时，预期结果可能是“无法判定”，不会用公开背景分数替代内容。

- H-T1 评判对象：分别比较 bundle 选中轨迹、创建表单行内 trace 和原始消息的特征与评分；任一对象不可取得则标为不可检验。
- H-T2 叙述质量：检查 setup、validation、computation、analysis、comparison 阶段覆盖，以及明确验证、错误后修复和失败恢复。
- H-T3 一致性：核对叙述中的输出与运行日志、结果和 characterization 的对应关系。
- H-T4 结构：比较步骤数分档和步骤类型多样性，先检查同包重复噪声再拟合。
- H-T5 元数据：模型与 harness 只作可观察关联，不把共同题目或时间造成的差异解释为因果效果。

预定评估是按题目分层的留一或留出测试，报告轨迹分绝对误差、≥70 与 ≥80 判定及所有误判；若无内容或同包重复，分别报告不可拟合与噪声未知。

## 本人轨迹可见性复查（2026-09-28）

当前[官方 Agent API 指南](https://play.bohrium.com/api/docs/dev/AGENT_API.md)指明 `GET /attempts/{id}/trace` 用于读取轨迹；已确认属于本项目实验邮箱的 3 条较新提交，既有认证取回的轨迹分别有 10、6、131 步，本轮用该邮箱凭据复查其中 1 条仍返回 10 步。所以“自己的提交不能查看轨迹”并不成立。针对 3 个由操作者确认关联的历史代理，使用操作者凭据逐条读取全部 72 条旧提交详情：72 次 HTTP 200，但 `traceCount` 全为 0，原始消息、bundle 和研究正文等内容字段均无值；三个代表提交的匿名和操作者身份 `/trace` 都返回空数组，操作者身份 `/bundle` 与 `/export-arm` 均返回 HTTP 403。操作者关联不等于代理本人的直接 token；项目密钥库没有这三个历史代理的 token。本轮不能证明平台后台从未保存轨迹，只能确认现有可用身份及官方只读入口取不回。脱敏统计和原始响应哈希保留于本机忽略目录 `.package-checks/trace-self-20260928/`；未修改平台资源。

随后按用户要求扩查全部当前登记代理及数据库邮箱：15 个已确认代理共 89 条可见提交，75 条有旧 0–100 轨迹分却无可取回的轨迹；另外 8 条有可取回的 API 轨迹却无旧轨迹分。列表标示有轨迹的 17 条中，9 条操作者读到空轨迹，自动导出均 403；5 份可取回 bundle 与 API 轨迹在成员和行数上并不总相同。完整可见性矩阵、源差异和证据边界见 [本人轨迹分析](OWNED_TRACE_ANALYSIS_2026-09-28.md)。当时检查的 API 和 CyberScientist 工作区中仍是 0 个配对样本；后续 AgentMaster 本地补证见下节。
