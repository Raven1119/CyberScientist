## 轨迹评分：W4 预登记

以下假设在分析轨迹分与特征关系前登记；缺少实时组的轨迹内容时，预期结果可能是“无法判定”，不会用公开背景分数替代内容。

- H-T1 评判对象：分别比较 bundle 选中轨迹、创建表单行内 trace 和原始消息的特征与评分；任一对象不可取得则标为不可检验。
- H-T2 叙述质量：检查 setup、validation、computation、analysis、comparison 阶段覆盖，以及明确验证、错误后修复和失败恢复。
- H-T3 一致性：核对叙述中的输出与运行日志、结果和 characterization 的对应关系。
- H-T4 结构：比较步骤数分档和步骤类型多样性，先检查同包重复噪声再拟合。
- H-T5 元数据：模型与 harness 只作可观察关联，不把共同题目或时间造成的差异解释为因果效果。

预定评估是按题目分层的留一或留出测试，报告轨迹分绝对误差、≥70 与 ≥80 判定及所有误判；若无内容或同包重复，分别报告不可拟合与噪声未知。

## 轨迹评分：W4 观察

`checks/evaluate_trace_evidence.py` 对 W2 的两张哈希核验表作独立汇总。71 条实时轮次记录都有轨迹分、模型与 harness 元数据，但 **0 条**同时有可取得的被评判轨迹特征。只有 3 个非实时评分包可读，不能与旧轨迹分配对。同包重复评分数为 0，重复噪声未知。

| 预登记假设 | 结果 |
|---|---|
| H-T1 评判对象 | 轮次内 bundle、表单行内 trace、原始消息均不可取得；无法判定具体评判对象。 |
| H-T2 叙述质量 | 没有配对轨迹，无法检验阶段覆盖、验证、错误修复或恢复。 |
| H-T3 一致性 | 没有配对日志与结果，无法计算轨迹内容一致性。 |
| H-T4 结构 | 没有配对步骤数和类型，无法检验分档或多样性。 |
| H-T5 元数据 | 71 条均有模型和 harness 字段，但没有配对轨迹特征；分数差异还受题目、时间与提交内容混杂，不能得出元数据效果。 |

本人实时组的轨迹分中，30/71 低于 70，33/71 低于 80，中位数 86.45。匿名背景组 3809 条公开提交中有 3406 条带轨迹分；其中 2004/3406（58.84%）低于 70，2182/3406（64.06%）低于 80，中位数 69。这些只是分布描述，不能作为内容特征的训练数据，也不能代表独立同分布验证集。

本轮可拟合样本数为 0；轨迹分绝对误差、≥70/≥80 准确率和误判条目均为**不可计算**，不是 0。没有产生经过验证的新预测器版本；生产中现有 `trace-placeholder-v1` 仍明确标低置信度占位，不把其返回的阈值布尔值称为实证保证。下一次具有原始轨迹与真实双分项的新轮次，才可按以上预登记特征先估计同包噪声，再做留出验证。
