# 事务性分诊导入

比赛轮次页在未确认轮次中粘贴 JSON，点击「导入用户分诊」。契约见 [TRIAGE_IMPORT_SCHEMA.json](TRIAGE_IMPORT_SCHEMA.json)。必须使用本轮公开题目 ID 和连接设置中已登记的求解者条目 ID。一次导入先完整校验，再原子应用；未知题目、重复 ID、未知条目、额外字段或密钥不会留下部分更新。每次原文和哈希保存为独立修订。助手调用前另存started尝试，取消结算interrupted且显示unknown；结果和旧分诊保存为历史。进程意外退出留下的started是未确认状态，不自动重发。

```json
[
  {
    "platform_challenge_id": "本轮公开题目ID",
    "priority": 10,
    "solver_entry": "连接设置中的条目ID",
    "data_status": "用户报告：数据可以下载，尚未验证完整性",
    "pi_notes": "先核对数据校验和；起步环境建议使用已验证的公共镜像。"
  }
]
```

优先级越大越先排队；相同优先级保留原顺序。页面按可提升空间显示的顺序与实际优先级队列分开。导入不创建 Run、不授权模型、算力或提交。随后仍需明确确认模板与授权。用户可以逐题覆盖条目、数据状态及事务提示；确认时冻结这些内容，开局 PI 收到注明来源的用户提示，不把它当已验证事实。备注仅用于数据状态、风险和环境建议，不能替代科学证据。

系统分诊是可选后备，受 `system_triage` 开关和显式模型授权控制，最多三题并行。每题一次原生助手会话，单次超时 900 秒；超时后先确认关闭，再仅对事务助手降一档重试一次。科研 PI 始终是 Astra xhigh。429、格式最终失败或关闭未知不会自动降档或重放；未知结果保留尝试记录，不填造难度或费用。原生结构化输出仍使用同会话最多两次格式重写。

API 可选 `operation_id`（1–100 字）在同一后端进程内重接尚在运行或最近 128 个已完成请求；关闭页面不杀死后台助手。此 ID 不跨重启持久化，不能据此宣称旧原生会话恢复。重启后需要用户重新授权；普通未提供 ID 的调用是独立授权，仍接受提供方并发/限速及安全关机门控。关闭失败保留租约与未知状态，安全关机重试关闭，确认退出才释放。
