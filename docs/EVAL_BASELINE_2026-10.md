## 已暴露的问题与后续方向（按当前影响排序）

1. **高：跨 Trial 最优候选未进入最终封存包。** Matchgate 第二轮 Q1、Q2 单题 Job 分别独立重放到 F=0.8002394885、0.8031740248，但最终 `outputs/submission.json` 保留身份占位线路，评分器对封存包两项只得 0.0001128899、0.0000088118。Q3 最终 F=0.6218737464 与独立评分器一致。应在封存前按每题候选哈希核对组合包，并对实际要封存的完整包做评分预检；本轮不能事后替换基线产物。
2. **高：稀疏审阅遗漏控制器拒绝反馈。** FigQA-0177 第一轮两次重复无效 `achieved` 证据引用，等待两轮 300 秒无进展检测后暂停。已把脱敏拒绝原因传给稀疏审阅并加有界即时复审；同一 Run 原生恢复后完成评分。该轮墙钟时间被故障污染。
3. **高：授权帧漏传沙箱边界与评测交接。** FigQA-0178 第一轮大脑误认没有沙箱额度而暂停。帧已补原授权的沙箱数量/分钟/GPU/数据下载事实，以及研究结束后系统独立评分的交接规则；同一 Run 恢复并得 100。未增加授权。
4. **高：大输入 Job 的取证状态与报告计数。** Lean 第一轮大输入上传超时且无平台 ID，必须记远端 unknown；第二轮与 Matchgate 第一轮各有一次本机 manifest 构造错误，请求未发出，已修复哈希变量遮蔽并留存 `not_started`。报告现分开统计已确认平台 Job 与远端 unknown 预约，本机失败不占平台 Job 数；仍无法得知未知预约是否实际计费。
5. **高：Lean 环境准备链路依赖大文件传输。** 已固定先前验证的公开 Lean/Mathlib 项目与归档哈希，评分前只转移依赖，不转移历史答案；首次准备在小文件 TLS 出错，唯一一次补评分在第三个 64 MiB 分块超时。该科学分不可用是基础设施结果，不能推断证明对错或评分器数值。后续需要验证可靠的分块传输或预构建镜像，再做有界同包评估。
6. **高：评分脚本 stdout 与依赖安装日志混流。** Matchgate 的原评分确实产生了完整 JSON，网关却因 pip 日志前缀拒绝记录。后续评分命令把依赖安装 stdout 导向 stderr，保持单 JSON 契约；本轮从经哈希及生命周期核对的原执行回执只读恢复分数。无远程确认的执行依旧不可按此方法恢复。
