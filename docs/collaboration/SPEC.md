# 非对称协作与静默监督：目标规格

状态：待实施。设计日期：2026-09-18。代码基线见 [CODE_AUDIT.md](CODE_AUDIT.md)。

## 1. 产品行为与不可变约束

### 要完成的研究闭环

执行器掌握局部代码、数据和实验细节，能够自主完成一段研究。大脑读取跨尝试的压缩证据，改进研究框架、提出观察要求和转向条件。两者都保留科学判断能力；大脑可以质疑执行器，执行器也可以用证据挑战指导。

```text
执行器原生事件 / 自然检查点 / 已登记实验结果
                      ↓
           既有控制器 → SQLite 事件与证据
                      ↓ 只读、有界投影
                ObservationFrame
                      ↓
       同一个大脑的独立审阅任务（单飞）
             ┌────────┴────────┐
          SILENT           INTERVENE
             ↓                 ↓
    大脑研究笔记 / 观察清单    持久化指导队列
    用户可见，执行器不可见      ↓ 安全边界投递
                            执行器确认 → 行动证据
```

| 不变量 | 可执行含义 |
|---|---|
| 非对称信息 | 大脑自动输入只能来自题面、经验快照、压缩观察帧和自己的研究笔记；不能把执行器完整聊天或原始推理流复制进去 |
| 真正静默 | 单纯观察或 SILENT 不能调用执行器的 prompt / steer / cancel，不能暂停执行器、改其目录/任务/经验快照或要求额外汇报 |
| 不阻塞执行 | 事件接收、控制请求、实验记账、SSE 和执行器工具返回，不等待大脑推理完成 |
| 一个大脑 | 被动观察与主动审阅共用一个大脑会话和一个排队入口，每个 Run 最多一个大脑 turn 在运行 |
| 有证据才更新认识 | 客观事件与执行器解释分别标来源；摘要不能凭空补分数、归因或“官方评分完成” |
| 受控介入 | 指导有固定目标 Trial、依据版本和投递记录；已发送、已收到、已采纳、已报告行动证据分开 |
| 失败隔离 | 静默审阅失败、超时或观察额度用尽，只停用/降级静默监督；执行器在原授权内继续。显式 blocking 请求仍保持等待 |
| 工程边界 | 原生 turn 结束不等于实验成功，取消会话不等于远程计算停止；原预算、暂停和提交授权始终有效 |

“静默”针对执行器，不针对用户。用户可以在 UI 查看大脑审阅和公开的研究笔记；不展示或要求保存模型内部思维链。观察也有模型和资源成本，不能承诺对墙钟时间完全无影响。

### 本轮保留与替换

复用当前单进程 FastAPI、SQLite、React、原生 Codex/Kimi 接入、经验修订和 SSE。大脑/执行器可以分别选择运行时；`prime/` 历史包名可暂留兼容，不为更名重写项目。新增功能不再依赖 Prime Agent。

不添加第三个摘要模型。控制器只投影结构化事实和执行器在自然研究节点已写下的报告；科学模式、归因和是否值得介入由大脑判断。缺少语义信息时标记未知；需要执行器额外分析时，必须作为一次可见介入，而不能伪装为被动观察。

## 2. 调度与指导如何工作

### 被动观察

常驻事件接收任务在后台读原生协议并持久化事件。观察帧生成器只读数据库和已登记的不可变结果元数据，不访问正在写入的文件，不触发新计算，不要求执行器停止。

大脑输入包括当前问题和方针、最近未审阅的科学变化、可比较实验结果、异常/反例、已确认的当前意图、预算和观察质量。保留事件范围 `from_seq..through_seq`、来源引用、遗漏数和未知字段；“最近 20 条事件类型”不能代替科学摘要。

摘要按「关键异常/失败 → 结果变化 → 当前意图 → 工具活动计数」保留。超出边界时显式报告截断和未读引用，不把未读取的文件内容当成已知。全局研究状态与增量帧组合使用，避免滚动窗口抹掉历史反例。

### 唤醒条件和防循环

新检查点、实验结果、已核实的评分变化、用户请求可以产生审阅请求；纯 stdout chunk、心跳、重复状态、大脑自己的笔记/决定/审阅完成事件不能直接触发大脑。稀疏定时器只检查是否有未审阅的有效变化；没有变化就不调用模型。

大脑忙时只合并尚未处理的事件范围，不为每条事件创建 turn。请求优先级为「用户硬控制 → 显式 blocking → 生命周期决策 → 其他请求/静默观察」；用户硬控制直接由控制器处理，不排队等待大脑。新请求不同时启动第二个大脑。

建议起始设置（工程默认值，可调整，不是已证明的最优值）：

| 配置 | 默认 | 行为 |
|---|---:|---|
| `shadow.enabled` | 新功能默认关闭，创建 Run 时可开启 | 历史 Run 不自动增加模型消耗；显式请求审阅仍可用 |
| `shadow.min_interval_seconds` | 60 | 合并普通观察请求；不拖延显式 blocking |
| `shadow.max_interval_seconds` | 600 | 有待观察变化时的稀疏兜底，不能突破最小间隔或预算 |
| `shadow.max_reviews` | 8 | 观察子额度受整个 Run 原有总额度约束，并为必要的主动审阅保留额度 |

配置在 Run 创建时快照化。UI 中关闭静默监督只停止新的被动审阅；使尚未投递的 shadow 来源指导失效，保留用户和显式请求。正在进行的静默审阅结果留历史，不再自动介入；不触碰执行器。已经被执行器确认的指导无法“撤销已发生动作”，需要用户另发明确指导。

同账户的请求额度紧张或限流时优先执行器和必要主动审阅，延后/停用被动观察。所有大脑调用计入 Run 用量；上游内部调用不可观测时显示未知，不报告为零。

### 两种审阅模式与原有生命周期

`shadow` 来自被动事件；`requested` 来自执行器检查点请求。使用同一大脑、同一调度器、不同提示词模式。新审阅结果必须在专用分支验证；不能未经限制送入旧 `_apply_decision` 产生新 Trial、finish 或平台动作。

Run 初始化、明确的实验交付后创建下一 Trial / finish，可继续复用旧生命周期 Decision；同样通过这一个串行大脑入口，不能再同步阻塞主事件处理。只有显式实验交付及已确认的回合边界才能触发生命周期换轮。

### 介入分级与科学内容

| 级别 | 内容 | 投递与效果 |
|---|---|---|
| `nudge` | 小提醒、回答一个问题、允许在原方针内继续 | 下一个自然检查点或空闲回合边界；不改变研究目标 |
| `steer` | 新观察要求、调整方针或重新表述问题 | 同样排队到安全边界；执行器确认后采纳或提出异议 |
| `stop` | 授权范围内要求停止扩展当前路线 | 控制器立即关闭新增受控工作入口，请求原生取消；确认后才显示已停，远程 Job 独立处理 |

指导必须说明“依据什么、改变什么、预期看到什么、什么结果需要重新讨论”。不计算虚假的介入收益数字；大脑基于宏观证据判断是否值得打断。观点分歧可以继续保留，优先提出能区分解释的小实验。

大脑维护最多三个当前重要的观察项：假说/风险、需要的证据和介入条件。它们是可修正的研究笔记，不是自动运行的规则引擎，也不自动晋升全局经验。

首版普通指导统一使用边界投递；Codex 的回合内 steer 可留为能力优化，不能成为闭环前提。Kimi ACP 忙碌时不反复调用其 steer，不为普通建议 cancel 正常研究。

## 3. 信息、经验与前端

### 大脑视图

为大脑设置独立且明确的工作目录和上下文入口，不再传 `working_directory=None`；不要放在会继承施工版 AGENTS 指令的目录下。自动挂载/注入内容不包含执行器完整工作区、数据库、原生日志或平台密钥。研究笔记只在大脑视图和 UI 可见；执行器只读取明确发布的指导。

通过可用的原生工具策略和权限回调限制大脑访问；实际测试跨目录读取。工作目录分开和 read-only 都不能单独证明操作系统级读取隔离。验收必须记录「实际输入隔离已验证」以及「原生工具访问边界的实测结果」；不能把未部署的沙箱写成已实现。本轮不为此新造沙箱平台。

### 经验

复用 `experiences.py` 的 Markdown、revision hash、冲突检测和回滚。大脑/执行器读的是选中修订的正文，不仅是标题和 hash；按全局/本题分别选择，有界注入。相同 Trial 使用固定版本；编辑默认影响下一 Trial，需要改变当前行为时必须发指导。

静默的 private note / watchlist 不修改经验，也不发布给执行器。明确经验候选需有关联证据、适用条件，走已有候选/晋升路径；继续保留失败、撤回与旧版本。不要在 SILENT 分支调用现有会自动保存/晋升经验的业务动作。

### 现有前端的最小扩展

在 `ResearchPage` 增加一个协作面板，复用现有 SSE 和 API：显示大脑状态、执行器状态、当前 Trial、审阅到哪个事件、摘要是否不完整、观察次数/用量、未确认指导及等待原因。原始事件列表保留。

| 用户操作 | 行为 |
|---|---|
| 开始 Run 时开启静默监督 | 纳入本轮配置和已有授权，不暗中追加费用范围 |
| “请大脑现在审阅” | 创建显式请求，返回 request ID；不直接重启执行器 |
| “关闭静默监督” | 只关闭被动观察，明确提示已发布指导仍可能有效 |

观察笔记和指导记录默认折叠，避免事件刷屏。状态必须明确区分「静默观察 / 正在审阅 / 监督不可用」与「执行中 / 等待大脑 / 暂停中 / 已暂停」。不能用大脑忙碌状态覆盖 Run 的运行状态。

完成标准是可复现的可靠协作闭环。能否提高科学得分仍需同总预算实测；本任务不以真实比赛得分提升作为工程验收的虚构结论。
