# 开赛第一小时评分器核对（CS-UP-11）

本文件是任务卡明确要求的运营核对步骤。它不授权任何提交；只有用户另行授权、且符合当时赛题边界的前一两次真实实验提交可用于核对。当前分析不提交 Attempt，也不执行他人的代码或复用其答案、产物、策略。

1. 在已授权提交前封存原始包、轨迹、题面、执行/产物回执的 SHA，记录工具与转换器版本。先确认题目存在；GET 404 重试一次，仍 404 就跳过并顺延。不要靠重新包装相同轨迹来制造新的独立样本。
2. 使用锁定公开 v6 源码计算 C、触发项、上限与 not_observable；使用独立双裁判脚本记录原始与训练映射后的预测，保留双裁判 P/H、缺失证据、配置和 packet SHA。副本当前未达验收，只能作提示。科学评分只按该题实际公布并已验证的评分入口记录；未知分项不补零。
3. 取最终回执，分别记录上传接受、科学评分来源、reward、harbor_score、四分项、trace_score、decision、displayScore、scoreIsFinal 和 trace_score_engine。HTTP 成功或 queued 不算最终得分。若仍评分中，标 pending 并按平台允许的读频率对账，不重新提交。
4. 与 S4 封存版本逐字段比较。引擎字符串变化直接标“版本标识变化”；有相同完整输入/回执且平台轨迹分超过本地上限 0.001，或最终科学分偏差超过 0.001，标“契约/输入需核对”。本地双裁判预测与平台轨迹分偏差超过 5 分、accept 分类不同，也触发人工复核；5 分只是此核对流程预设的报警阈值，不是统计显著性或 v8 已证明的误差界。
5. 只有一两例时不能推断新权重、触发条件或新阈值。先排查轨迹转换丢行、公开字段遮蔽、文件选择、字符截断、redaction、worker 回执缺失、单位和非最终回执。缺少平台实际输入时保留 unknown，不能把差异全部归因于评分器升级。
6. 确认需要重校准后，新建版本目录并冻结来源/配置；取得新的、多题覆盖且有界授权的数据集，按题拆训练/新留出集。在训练集选择分数 MAE 更低的候选与映射，预先固定分类验收线 85%/被拦抓出率 80%，再一次性评价新留出。S4 已查看过的 24 例不得重新称为盲留出，也不得用于调参。保留旧版全部输入/输出/失败与 unknown。

记录表至少包含 attempt_id、challenge_id、时间、源码/转换器/输入 SHA、模型请求别名与实际标识可见性、引擎字符串、各预测/最终分、最终状态、差异类别、可证实原因和 unknown。只将真实核对事实写入状态和诊断，不把评分观察转成任务解题经验或策略。
